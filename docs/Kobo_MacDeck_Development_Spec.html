Kobo MacDeck

將 Kobo Clara BW 改造為雙模式 E-Ink 桌面時鐘與 macOS 無線觸控控制器。以 KOReader 插件承載介面、Bluetooth 優先傳遞控制事件、Wi-Fi 提供背景資訊同步，並保留完整退出路徑。

Idle ClockMac ControlSoftware-only IdleBluetooth-first
目標硬體Kobo Clara BW
執行環境KOReader + NickelMenu
主要主機macOS / MacBook Pro
文件狀態規劃版本，非已驗證實作

01 · 專案摘要

核心體驗：開啟 MacDeck 後先顯示時鐘資訊頁。使用者觸控頁面進入控制介面，由 Kobo 發送遠端操作命令給 Mac。長時間無操作時自動返回時鐘；任何活動頁面始終可退出 MacDeck，回到 KOReader。

關鍵設計原則：本專案中的 Idle 是插件自訂的 UI 狀態，不是 Kobo 原廠 Suspend / Sleep。不得使用實體電源鍵作為模式切換入口，亦不得承諾系統真正休眠時仍可每分鐘更新時間。

成功定義

即使 Bluetooth 無法實現，第一版仍可驗收「時鐘 + 觸控界面 + 返回 KOReader」；完整產品驗收則要求至少一種已測通的 Mac 通訊方式，以及可靠的控制事件回饋。

02 · 需求、非目標與假設

ID優先級規格驗收方式
FR-01P0插件啟動後進入橫向 Clock/Idle 頁可顯示時間及可操作入口
FR-02P0時鐘每分鐘更新一次，對齊分鐘邊界，不顯示秒數觀察連續 15 分鐘
FR-03P0Clock 點擊進入 Controller，非電源鍵觸控測試
FR-04P0Controller 顯示 6–9 個大面積控制鍵介面與觸控測試
FR-05P0Clock / Controller 均有 Exit，關閉插件返回 KOReader連線中斷時仍可退出
FR-06P0Controller 無觸控逾時返回 Clock，預設 60 秒可設定逾時測試
FR-07P1Bluetooth 控制 Mac；需先完成實機協定能力檢查雙向訊息與成功率測試
FR-08P1Wi-Fi 同步天氣、行事曆；支援離線快取斷網及恢復測試
FR-09P1藍牙失敗時顯示狀態，允許選用 Wi-Fi 備援斷線測試
FR-10P2Mac 前景 App 狀態自動映射控制鍵切換應用程式測試

明確非目標

  • 不將 Kobo 當作低延遲滑鼠、連續觸控板或外接顯示器。
  • 不要求安裝 Home Assistant、Docker、完整桌面 Linux 或重新刷入韌體。
  • 不鏡像 iPhone 所有通知；只讀取使用者授權的特定來源。
  • 不在插件內接管 Kobo 實體電源鍵的原廠功能。
  • 不允許遠端執行任意 Shell 字串。

現況 / 未驗證

已知 Clara BW 已可運行 KOReader、NickelMenu、第三方 .koplugin；待驗證 MTK Bluetooth stack 是否可提供 BLE GATT Client、BLE Peripheral 或 HID Device。這是專案能否採用藍牙的硬性 Gate，不能視為已完成能力。

03 · 系統架構

資料來源天氣 / iCal / 授權通知來源
→
Kobo / MacDeck資料快取 + UI + 狀態機 + 觸控
⇄
Mac Companion命令驗證 + macOS Automation

資料與命令分離：Wi-Fi 用於 Clock 頁的低頻網路資訊；Bluetooth 優先用於 Controller 到 Mac 的離散操作。兩者切換策略不應預設硬體必然支援並行工作，需在實機測試後決定是否重用 Wi-Fi 備援。

KOReader 端

  • Lua UI：大按鈕、時鐘、連線狀態與 Exit。
  • State machine：Idle / Connecting / Active / Offline。
  • 資訊快取與低頻排程。
  • Transport adapter：BLE 與 Wi-Fi 用同一命令介面。
  • 安全恢復原始 KOReader 設定。

Mac 端

  • Swift/CoreBluetooth（BLE GATT 路線）或 Wi-Fi 本地服務。
  • Hammerspoon / AppleScript / Shortcuts 控制系統。
  • 預先定義的指令白名單。
  • 傳回狀態 ACK、錯誤、前景 App 等。
  • 僅在使用者許可下存取系統權限。

04 · 狀態機與轉換

當前狀態事件下一狀態行為
INIT開啟插件CLOCK載入快取、畫出時鐘，排程更新
CLOCK觸控「控制」區域CONNECTING初始化藍牙連線；始終保留返回按鈕
CONNECTING連線成功CONTROL顯示 Mac 操作鍵與連線狀態
CONNECTING逾時或失敗OFFLINE顯示 Retry / Wi-Fi Fallback / Clock / Exit
CONTROL觸控快捷鍵CONTROL發送允許的 command、短暫顯示 ACK
CONTROL / OFFLINE閒置逾時或 Clock 鍵CLOCK關閉／降載控制傳輸，恢復資訊頁
任何插件頁ExitKOReader清理 timer、還原 UI/電源設定、關閉插件視窗
任何插件頁系統強制 suspend系統處理不攔截電源鍵；恢復後重算時間與網路狀態

安全性不變條件：所有連線等待與錯誤畫面都必須有可用的退出功能；不得等待藍牙初始化完成才能返回 KOReader。插件異常也不能阻斷原廠電源鍵。

5.4 介面原則

  • 對外顯示繁體中文或英文短標籤，文字可自訂，避免整頁密集資訊。
  • 主要觸控操作應只需一次點擊；高風險操作（鎖定／結束會議等）可選擇確認。
  • 網路資料失敗時顯示上次同步時間，不以空白畫面取代整個時鐘。
  • 禁止任何無法中止的連線進度畫面。

06 · Bluetooth 與 Wi-Fi 通訊協定

6.1 Transport 決策 Gate

  1. 唯讀確認 MTK 藍牙服務、D-Bus API 與硬體功能。
  2. 驗證 Kobo 能否作為 BLE GATT Client 寫入 Mac 提供的服務；若失敗，另研究 Kobo Peripheral / HID，但不假設支援。
  3. 最小成功測試：Kobo 送 PING、Mac 回 ACK，50 次測試的成功率滿足目標。
  4. 若上述功能無可靠通路，採用 Wi-Fi 本地 HTTP/WebSocket 備援，避免更動底層驅動造成不穩定。

6.2 訊息 Envelope（草案）

{
  "protocol": "macdeck/1",
  "id": "cmd-000042",
  "timestamp_ms": 1793223600000,
  "type": "command",
  "action": "media.toggle",
  "args": {},
  "session": "paired-session-id"
}

以上是應用層格式，供 BLE characteristic payload 或 Wi-Fi body 使用。BLE 封包可能需使用 CBOR 或分段編碼，不能假設單筆可直接承載整段 JSON。session 不是秘密值，安全仍需配對與訊息驗證。

6.3 回覆格式

{
  "protocol": "macdeck/1",
  "id": "cmd-000042",
  "type": "ack",
  "status": "ok",
  "detail": "media.toggle executed"
}

6.4 控制動作白名單

Action執行範圍失敗處理
app.activate只允許預先設定的 App ID顯示 App 不存在
media.toggle播放／暫停ACK error
audio.mute切換靜音回傳目前狀態
screen.capture呼叫已授權的 Mac 捷徑權限不足時提示
workflow.run執行白名單 workflow ID不得傳入任意 shell
mac.lock鎖定 Mac確認操作及防誤觸

6.5 可靠傳輸

  • 每筆指令必須有唯一 id；Mac 端須去重，避免重試造成重複操作。
  • 首版採用「送出 → ACK」；建議 ACK timeout 2 秒、最多 2 次重試（均待實測）。
  • 連線狀態只能顯示已確認資訊，不能把 BLE 配對成功當作命令成功。
  • 同步模式明確區分資料推送與控制事件，避免不同網路邏輯互相阻塞。

07 · 排程、刷新與快取

項目頻率策略
時鐘每分鐘一次對齊整分鐘，只刷新時間區塊
日期跨日更新日期欄位
天氣預設 30 分鐘Wi-Fi 抓取與本地快取，失敗保留最後值
行事曆預設 15 分鐘僅渲染有變動的行程
通知摘要可選 5–15 分鐘僅取使用者授權來源，不直接鏡像 iOS
Controller事件觸發命令回覆只做必要局部刷新
Full refresh視殘影測試每 30–60 分鐘作為初始調整值，不是硬性要求

對齊分鐘的排程原理

now = os.time()
seconds_to_next_minute = 60 - (now % 60)
-- 設定一次性 timer；觸發後重新計算下一次時間
-- 恢復前台、重新連線、系統時鐘變動時重新對齊

UI timer 不應阻塞事件迴圈，也不應以固定 60 秒遞迴造成長期漂移。跨 DST、手動改時區、背景恢復時應重新讀取本機時間。

08 · 電源管理與 KOReader 生命週期

既定設計：Clock 與 Controller 是軟體畫面狀態。插件活躍期間需要持續執行 UI 事件迴圈才能每分鐘更新時鐘；不主動觸發原廠休眠。

  • 首次進入插件時記錄必要的 KOReader 原始自動休眠、螢幕方向及前光設定。
  • 插件活動期間僅暫時覆蓋真正需要的設定；退出、失敗及非預期中斷時優先恢復。
  • 實體電源鍵由系統既有機制處理；不把它當作 Clock → Control 入口。
  • 若使用者手動讓系統 Suspend，時鐘畫面可以保留最後影像但無法持續依分鐘更新；恢復後重新計算排程。
  • 藍牙初始化需提供取消與超時；避免耗電的無限掃描。
  • 不預設 Wi-Fi 和 Bluetooth 必然可同時穩定運作，先量測共存行為。

由於程序持續運行，E-Ink 畫面靜止不代表系統接近零耗電。長期續航需要以實際待機電流、Wi-Fi 使用時間、藍牙掃描負載評估，不能僅以畫面刷新頻率推算。

09 · 安全與權限

  • 僅允許已配對且經使用者核准的 Mac 接收指令；首次配對要有可見確認流程。
  • 應用層訊息要有命令 ID、重放防護、短時有效性、去重與指令白名單；BLE 加密與綁定仍需依實際堆疊能力確認。
  • Mac Companion 僅在區域環境監聽，禁止開放公網埠；Wi-Fi 備援採明確配對 Token 並保護傳輸。
  • 日誌不得儲存私密行事曆全文、密碼、Cookie、配對密鑰或完整通知內容。
  • Mac 端的 Automation / Accessibility 權限採最小權限原則。
  • 可一鍵解除配對，並清除本機儲存的連線設定。

11 · 開發里程碑與決策點

Phase 0 — 現況備份與硬體調查

記錄韌體、KOReader 版本、啟動路徑及藍牙程序。備份相關配置。僅執行唯讀命令，完成 MTK BLE API 能力清單。

交付 Device Capability Report

Phase 1 — UI MVP

建立 Clock / Controller / Exit，先使用假的 Mac 指令測試按鈕。確認橫向渲染、每分鐘刷新與逾時返回。

交付 macdeck.koplugin 最小可運作版本

Phase 2 — 傳輸驗證 Gate

研究 BLE GATT Client 寫入、Mac Peripheral Manager 服務與配對；PING / ACK 可靠度測試。失敗則切換 Wi-Fi 備援，禁止以無證據前提投入 HID 模擬。

交付 Bluetooth Feasibility Decision

Phase 3 — Mac Companion

接通固定白名單 Action、ACK、配對、錯誤處理。至少 6 個操作可用。

交付 Mac 控制接收程式與使用說明

Phase 4 — StandBy 資訊服務

Wi-Fi 天氣 / 行事曆資料源、快取與最後更新時間；檢查斷網和慢速網路行為。

交付 完整 Clock 畫面

Phase 5 — 穩定性 / 使用者測試

多次進退插件、拔除網路、Mac 睡眠重連、長時運行、觸控誤觸、原廠閱讀功能回歸測試。

交付 Release Candidate + 測試報告

13 · 風險、待確認事項

風險等級緩解方式
MTK 藍牙未提供自訂 GATT / HID 能力高Phase 0/2 設驗證 Gate，Wi-Fi fallback

Open Decisions

  1. Clara BW 實際韌體版號與 KOReader Runtime API 詳細版本。
  2. BT 角色：BLE GATT Client、Peripheral、HID Device 哪一個可測通？
  3. 是否需要 Mac App 自動切換按鈕配置？屬 P2，先不阻擋 MVP。
  4. 天氣 API、行事曆來源與位置資料策略。
  5. USB 插電時是否始終保持 Clock 運行；拔電後是否調整更新節奏。
